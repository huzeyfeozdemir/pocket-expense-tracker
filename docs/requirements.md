# Requirements — Pocket Expense Tracker

## 1. Purpose

A personal, mobile-friendly web app that works like a **"fitness tracker for money"**.
I use several banks, so my spending is split across different apps. This app **combines the statements from all my banks into one place**, shows where my money goes, and gives me simple advice to manage my budget better.

- **User:** Only me (personal use).
- **Platform:** Web app that runs in the phone browser and can be added to the home screen.
- **Data:** Stored only on my own device.

## 2. Scope by version

| Version | Goal |
|---|---|
| **v1 — One view for all banks** | Import statements from multiple banks, auto-categorize, ask me about unknown transactions, combined monthly summary and chart |
| **v2 — Budgets & goals** | Category budgets, saving goals, month-to-month comparison, euro support |
| **v3 — Coach** | Weekly "Finance Score", streaks and rule-based tips |
| **v4 — AI coach** | Personal advice generated by an AI model (optional, later) |

## 4. Categories (first version)

**Expenses:** Food · Groceries · Transport · Bills (phone, internet) · Entertainment · Clothing · Subscriptions · Education · Personal care · Shopping · Sent to people · Other
**Income:** Scholarship · Family · Salary · Other income
**Excluded from totals:** Transfer between my accounts · Credit card payment (only when the card statement is imported)
**Fallback:** Credit card (no details) — used when the card statement is not imported

Categories can be changed later.

## 5. Data to store

- **Account:** id, bank name, account name, type (bank account / credit card)
- **Transaction:** id, account, date, description (as written in the statement), amount, currency, type (income / expense / transfer), category, source (import / manual), needs review (yes / no)
- **Rule:** keyword found in the description (e.g. "NETFA" — dorm cafeteria / café), category to assign
- **Import:** id, account, file name, import date — to know which statements were already uploaded

## 6. Technical decisions

- **Frontend:** HTML, CSS, JavaScript
- **Storage:** SQLite running inside the browser, so all analysis is done with SQL queries
- **File import:** Text-based PDF statements first (the format my banks give), Excel / CSV later
- **Hosting:** GitHub Pages (free)

## 7. Banks (first version)

| Bank | Statement format checked | Notes |
|---|---|---|
| Kuveyt Türk | PDF (text) | Each transaction has a unique reference code — useful to detect duplicates |
| Yapı Kredi | PDF (text) | Date and time per transaction; long descriptions wrap to two lines |
| Ziraat Bankası | PDF (text) | Must be downloaded from internet banking: the mobile app gives an image-only PDF that cannot be read. Columns are split across pages. |

Real statements contain personal data (IBAN, address, names) and are **never** added to this repository. Tests use made-up sample files.

## 8. Open questions

- What do credit card statements look like (installments, statement period)? → planned after v1.
